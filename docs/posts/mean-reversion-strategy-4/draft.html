In Part 1 we derived \mathrm{SR}_\infty = \sqrt{\theta/2} assuming perfect knowledge of the OU parameters. Part 2 showed that a constant bias M in the fair-value estimate incurs a penalty (1 + 2\theta M^2/\sigma^2)^{-1/2}. Part 3 extended this to correlated bias, proving that any trailing estimator degrades both expected PnL and risk.

All three parts treated the OU parameters \theta and \sigma as known. In practice, these must be estimated from a finite calibration sample — and estimation error feeds directly into the trader’s fair-value estimate. This post closes the loop by asking: how does parameter estimation error affect the realised Sharpe ratio?

The answer has two distinct channels:

  • Mean estimation error (\hat\mu \neq 0): the estimated long-run mean \hat\mu acts as a constant bias in the Part 2 sense. Its variance \mathrm{Var}(\hat\mu) \approx \sigma^2/(\theta^2 T_{\mathrm{est}}) yields a clean penalty (1 + 2/(\theta T_{\mathrm{est}}))^{-1/2}, governed by the number of mean-reversion half-lives in the calibration window.
  • Speed estimation error (\hat\theta \neq \theta): the finite-sample bias in \hat\theta does not degrade realised SR (which is scale-invariant), but creates systematic overconfidence — the trader predicts a higher SR than is actually achieved, leading to misallocated capital and underestimated drawdowns.

We also show that rolling re-estimation is equivalent to a Part 3 trailing estimator, unifying the estimation-error penalty with the correlated-bias penalty from the previous post.

# --- OU helpers (same conventions as Parts 1–3) ---

def s2(t, theta, sigma):
    """Variance of X_t: sigma^2/(2*theta) * (1 - exp(-2*theta*t))."""
    return sigma**2 / (2 * theta) * (1 - np.exp(-2 * theta * t))


def simulate_ou(theta, sigma, T, dt, n_paths, mu=0.0, rng=rng):
    """Euler–Maruyama: dX = -theta*(X - mu) dt + sigma dW, X_0=mu."""
    n_steps = int(T / dt)
    X = np.full((n_paths, n_steps + 1), mu)
    sqrt_dt = np.sqrt(dt)
    for i in range(n_steps):
        dW = rng.standard_normal(n_paths) * sqrt_dt
        X[:, i + 1] = X[:, i] - theta * (X[:, i] - mu) * dt + sigma * dW
    return X


def pnl_paths(X, M, dt):
    """PnL paths: dY = -(X - M) dX.

    M can be: scalar, 1-D array (n_paths,) for per-path constant bias,
    or 2-D array (n_paths, n_steps+1) for time-varying bias.
    """
    dX = np.diff(X, axis=1)
    X_mid = X[:, :-1]
    if np.ndim(M) == 2:
        M_mid = M[:, :-1]
    elif np.ndim(M) == 1:
        M_mid = M[:, None]
    else:
        M_mid = M
    dY = -(X_mid - M_mid) * dX
    Y = np.cumsum(dY, axis=1)
    return np.concatenate([np.zeros((X.shape[0], 1)), Y], axis=1)


# --- MLE for the OU process (exact discretisation) ---

def mle_ou(X_path, dt):
    """MLE for a single OU path via AR(1) regression.

    X_{i+1} | X_i ~ N(a*X_i + b, s2_eps)
    where a = exp(-theta*dt), b = mu*(1 - a), s2_eps = sigma^2/(2*theta)*(1-a^2).

    Returns (theta_hat, mu_hat, sigma_hat).
    """
    y = X_path[1:]
    x = X_path[:-1]
    n = len(y)
    # OLS: y = a*x + b + eps
    Sx = np.sum(x)
    Sy = np.sum(y)
    Sxx = np.sum(x * x)
    Sxy = np.sum(x * y)
    denom = n * Sxx - Sx * Sx
    a_hat = (n * Sxy - Sx * Sy) / denom
    b_hat = (Sy - a_hat * Sx) / n
    # Clamp a_hat to avoid log of non-positive or unit root
    a_hat = np.clip(a_hat, 1e-12, 1 - 1e-6)
    theta_hat = -np.log(a_hat) / dt
    # mu_hat = b/(1-a); fall back to sample mean when a ≈ 1
    if abs(1 - a_hat) < 1e-4:
        mu_hat = np.mean(X_path)
    else:
        mu_hat = b_hat / (1 - a_hat)
    # Residual variance
    eps = y - a_hat * x - b_hat
    s2_eps = np.mean(eps**2)
    sigma_hat = np.sqrt(2 * theta_hat * s2_eps / (1 - a_hat**2))
    return theta_hat, mu_hat, sigma_hat

1 MLE for the OU Process

We work with the same centred OU model as Parts 1–3:

dX_t = -\theta\,(X_t - \mu)\,dt + \sigma\,dW_t, \qquad X_0 = \mu.

For the trading strategy, X_t is the mispricing (deviation from fair value v, with \mu = v the true long-run mean). The trader must estimate (\theta, \mu, \sigma) from a calibration sample of length T_{\mathrm{est}}.

As derived in a previous post, the exact discretisation of the OU process is:

X_{i+1} \mid X_i \;\sim\; \mathcal{N}\!\big(\underbrace{X_i\,e^{-\theta\Delta t} + \mu(1 - e^{-\theta\Delta t})}_{\mu_i},\;\; \underbrace{\tfrac{\sigma^2}{2\theta}(1 - e^{-2\theta\Delta t})}_{\Sigma_i}\big).

This is a Gaussian AR(1) model X_{i+1} = a X_i + b + \varepsilon_i with a = e^{-\theta\Delta t} and b = \mu(1-a), so MLE reduces to OLS regression. Inverting:

\hat\theta = -\frac{\log\hat{a}}{\Delta t}, \qquad \hat\mu = \frac{\hat{b}}{1-\hat{a}}, \qquad \hat\sigma^2 = \frac{2\hat\theta\,\hat{s}^2_\varepsilon}{1-\hat{a}^2}.

Three finite-sample difficulties plague this estimator:

  1. Identification. When \theta is small, a \approx 1 and the process resembles a random walk. The product \mu(1-a) makes \hat\mu and \hat\theta strongly correlated — a slight change in one can be compensated by the other.
  2. Bias. The MLE \hat\theta is upward-biased in finite samples: small-sample variability causes \hat{a} to be pulled below e^{-\theta\Delta t}, inflating \hat\theta. Conversely, \hat\mu is biased toward the sample mean, which for short samples may not have had time to “find” the true \mu.
  3. Variance. All three estimators have high variance when \theta T_{\mathrm{est}} is small — the process hasn’t completed enough mean-reversion cycles to reveal its parameters.

2 The Estimation Penalty on Sharpe Ratio

2.1 Setup: one-shot estimation then trading

The trader observes the OU process on a calibration window [0, T_{\mathrm{est}}], estimates (\hat\theta, \hat\mu, \hat\sigma) via MLE, then trades on [T_{\mathrm{est}}, T_{\mathrm{est}} + T_{\mathrm{trade}}] using \hat\mu as the fair-value estimate.

From Part 2, the asymptotic Sharpe ratio when trading with a constant bias M is:

\mathrm{SR}_\infty = \sqrt{\frac{\theta}{2}} \cdot \frac{1}{\sqrt{1 + \dfrac{2\theta M^2}{\sigma^2}}}.

Part 2 also showed that expected PnL is unchanged by a constant bias — the degradation acts purely through increased variance. This means estimation error in \hat\mu acts exactly as a Part 2 constant bias during the trading window (since \hat\mu is fixed once estimated and independent of the future Brownian increments on [T_{\mathrm{est}}, T_{\mathrm{est}} + T_{\mathrm{trade}}]).

2.2 Variance of \hat\mu

For a stationary OU process with mean \mu, the sample mean \bar{X} = \frac{1}{T}\int_0^T X_t\,dt satisfies:

\mathrm{Var}(\bar{X}) = \frac{1}{T^2}\int_0^T\!\int_0^T \mathrm{Cov}(X_s, X_t)\,ds\,dt = \frac{\sigma^2}{\theta^2 T}\left(1 - \frac{1 - e^{-\theta T}}{\theta T}\right).

For large \theta T (many half-lives), \mathrm{Var}(\bar{X}) \approx \sigma^2/(\theta^2 T). The MLE \hat\mu coincides with \bar{X} asymptotically, so:

\mathbb{E}[\hat\mu^2] = \mathrm{Var}(\hat\mu) \approx \frac{\sigma^2}{\theta^2 T_{\mathrm{est}}}.

2.3 The penalty formula

Substituting M^2 \to \mathbb{E}[\hat\mu^2] into the Part 2 formula (just as we substituted M^2 \to \sigma_M^2 for random independent bias in Part 3):

\boxed{\mathrm{SR}_\infty = \sqrt{\frac{\theta}{2}} \cdot \frac{1}{\sqrt{1 + \dfrac{2}{\theta\, T_{\mathrm{est}}}}}.}

The penalty factor \left(1 + 2/(\theta T_{\mathrm{est}})\right)^{-1/2} depends only on the dimensionless product \theta T_{\mathrm{est}} — the number of mean-reversion timescales observed during calibration. To achieve a penalty smaller than 1/\sqrt{2} \approx 0.71, we need \theta T_{\mathrm{est}} > 2, i.e., we must observe at least two full mean-reversion timescales.

# --- SR vs estimation window: theory + MC ---
theta_true, sigma_true, mu_true = 1.0, 1.0, 0.0
dt = 1 / 252
T_trade = 100         # long trading window for asymptotic SR
n_mc = 2000           # MC paths for estimation

T_est_grid = np.array([1, 2, 3, 5, 7, 10, 15, 20])
sr_theory = np.sqrt(theta_true / 2) / np.sqrt(1 + 2 / (theta_true * T_est_grid))
sr_mc = []

for T_est in T_est_grid:
    pnl_per_year = []
    qvY_per_year = []
    for i in range(n_mc):
        seed_est = int(10000 * T_est + i)
        X_full = simulate_ou(theta_true, sigma_true, T_est + T_trade, dt, 1,
                             mu=mu_true, rng=np.random.default_rng(seed_est))
        n_est_steps = int(T_est / dt)
        X_cal = X_full[0, :n_est_steps + 1]
        X_trade = X_full[:, n_est_steps:]  # keep 2D

        _, mu_hat, _ = mle_ou(X_cal, dt)

        # PnL and QV of Y (not X)
        Y = pnl_paths(X_trade, mu_hat, dt)
        pnl_per_year.append(Y[0, -1] / T_trade)
        dX_tr = np.diff(X_trade, axis=1)
        dY = -(X_trade[:, :-1] - mu_hat) * dX_tr
        qvY = np.sum(dY**2, axis=1)[0]
        qvY_per_year.append(qvY / T_trade)

    mean_pnl = np.mean(pnl_per_year)
    mean_qvY = np.mean(qvY_per_year)
    sr_mc.append(mean_pnl / np.sqrt(mean_qvY))

sr_mc = np.array(sr_mc)

3 Why the Correlation Channel is Transient

In Part 3, we showed that a correlated bias degrades expected PnL via -\theta\int_0^t \mathrm{Cov}(M_u, X_u)\,du, not just risk. Does the one-shot estimator \hat\mu — computed from the calibration window — introduce this extra penalty?

The answer is no, asymptotically. The key observation is the Markov property of the OU process: X_t for t > T_{\mathrm{est}} depends on the calibration window only through X_{T_{\mathrm{est}}}. Since \hat\mu is a function of \{X_s : s \leq T_{\mathrm{est}}\}, we have:

\mathrm{Cov}(\hat\mu, X_t) \;=\; \mathrm{Cov}\big(\hat\mu, X_{T_{\mathrm{est}}}\big) \cdot e^{-\theta(t - T_{\mathrm{est}})}, \qquad t > T_{\mathrm{est}}.

This decays exponentially as we move into the trading window. The cumulative PnL degradation from the Part 3 covariance channel is:

\frac{\theta}{T_{\mathrm{trade}}}\int_{T_{\mathrm{est}}}^{T_{\mathrm{est}}+T_{\mathrm{trade}}} \mathrm{Cov}(\hat\mu, X_t)\,dt \;=\; \mathrm{Cov}(\hat\mu, X_{T_{\mathrm{est}}})\cdot\frac{1 - e^{-\theta T_{\mathrm{trade}}}}{T_{\mathrm{trade}}} \;\to\; 0

as T_{\mathrm{trade}} \to \infty. The correlation effect is washed out by the long trading horizon.

Therefore, for one-shot estimation, the entire SR penalty comes from the Part 2 variance channel: \hat\mu acts as a random constant bias with \mathbb{E}[\hat\mu^2] \approx \sigma^2/(\theta^2 T_{\mathrm{est}}), giving the clean formula (1 + 2/(\theta T_{\mathrm{est}}))^{-1/2}.

4 Rolling Estimation Unifies Parts 3 & 4

In practice, traders don’t estimate \hat\mu once and trade forever — they re-estimate continuously using a rolling window of length W. At each time t, the fair-value estimate is the trailing sample mean:

M_t = \frac{1}{W}\int_{t-W}^{t} X_s\,ds.

This is precisely a simple moving average (SMA) — a trailing estimator covered by Part 3’s general theorem. Since the weighting kernel w(s) = \mathbf{1}_{[0,W]}(s)/W is non-negative and integrates to 1, Part 3 tells us that \mathrm{Cov}(M_t, X_t) > 0 always — rolling re-estimation creates the persistent correlated-bias penalty that the one-shot estimator avoids.

The SMA with window W has a characteristic timescale of W/2, analogous to an EMA with decay rate \lambda \approx 2/W. Substituting into Part 3’s EMA Sharpe formula:

\mathrm{SR}_\infty = \frac{\theta}{\sqrt{2(\theta + \lambda)}} = \frac{\theta}{\sqrt{2(\theta + 2/W)}} = \sqrt{\frac{\theta}{2}} \cdot \frac{1}{\sqrt{1 + \dfrac{2}{\theta W}}}.

This is the same functional form as the one-shot penalty, with the rolling window W replacing T_{\mathrm{est}}. The unification is satisfying but reveals a crucial asymmetry:

Method Penalty Source
One-shot (calibrate then trade) (1 + 2/(\theta T_{\mathrm{est}}))^{-1/2} Part 2 variance channel only
Rolling window W (1 + 2/(\theta W))^{-1/2} Part 3 covariance channel (dominant)

The one-shot penalty vanishes as T_{\mathrm{trade}} \to \infty (keeping T_{\mathrm{est}} fixed), while the rolling penalty persists forever — it is a structural cost of continuous re-estimation.

Code 
# --- Rolling estimation: SMA bias simulation ---
theta_true, sigma_true = 1.0, 1.0
dt = 1 / 252
T = 50                 # total simulation length
n_paths = 2000
W_values = [0.5, 1, 2, 5, 10, 20]

sr_rolling_mc = []

for W in W_values:
    W_steps = int(W / dt)
    X = simulate_ou(theta_true, sigma_true, T, dt, n_paths,
                    rng=np.random.default_rng(123))
    # Compute rolling SMA bias: M_t = (1/W) * integral_{t-W}^{t} X_s ds
    cumX = np.cumsum(X, axis=1) * dt
    M = np.zeros_like(X)
    for k in range(W_steps, X.shape[1]):
        M[:, k] = (cumX[:, k] - cumX[:, k - W_steps]) / W

    # Only measure SR after the window is fully populated
    burn = W_steps + int(5 / dt)
    if burn >= X.shape[1] - int(5 / dt):
        burn = W_steps
    X_eval = X[:, burn:]
    M_eval = M[:, burn:]
    T_eval = (X_eval.shape[1] - 1) * dt

    # SR = mean(annualised PnL) / sqrt(mean(annualised QV_Y))
    Y = pnl_paths(X_eval, M_eval, dt)
    mean_pnl = np.mean(Y[:, -1] / T_eval)
    dX_eval = np.diff(X_eval, axis=1)
    dY = -(X_eval[:, :-1] - M_eval[:, :-1]) * dX_eval
    qvY = np.sum(dY**2, axis=1)
    mean_qvY = np.mean(qvY / T_eval)
    sr_rolling_mc.append(mean_pnl / np.sqrt(mean_qvY))

sr_rolling_mc = np.array(sr_rolling_mc)

5 The Overconfidence Trap: Bias in \hat\theta

The MLE overestimates \theta in finite samples (the median \hat\theta exceeds the true \theta, as we saw in the histograms above). Does this degrade the realised Sharpe ratio?

No. The realised SR = Y_T / \sqrt{[X]_T} depends only on the actual mispricing process and the trader’s fair-value estimate — it is scale-invariant in \theta. Using \hat\theta instead of \theta for position sizing simply scales positions up or down uniformly, which cancels in the SR ratio.

The danger is subtler: the trader predicts \mathrm{SR}_\infty = \sqrt{\hat\theta/2}, which (because \hat\theta is upward-biased) is systematically too high. This creates:

  • Over-allocated capital: the trader believes the strategy is more profitable than it is, and allocates more capital / higher leverage.
  • Underestimated drawdowns: risk budgets calibrated to the inflated SR will be too tight, triggering premature stop-outs.
  • Misranked strategies: in a portfolio of strategies, the one with the shortest calibration window looks best — but only because its \hat\theta is most biased.

6 Reducing Estimation Error with Particle Filtering

As shown in a previous post, particle filtering produces tighter, better-centred distributions of (\hat\theta, \hat\mu, \hat\sigma) compared to MLE. The PF maintains a cloud of parameter hypotheses (particles), updates their weights sequentially as new data arrives, and uses resampling + MCMC moves to avoid particle degeneracy.

We implement a simplified particle filter here and compare its effect on the trading strategy’s realised Sharpe ratio. The key question: does tighter parameter estimation actually translate into higher realised SR?

Code 
# --- Simplified particle filter for OU parameters ---

def ou_log_likelihood(r_prev, r_curr, kappa, theta, sigma, dt):
    """Log-likelihood of one OU transition (exact discretisation)."""
    mean = r_prev * np.exp(-kappa * dt) + theta * (1 - np.exp(-kappa * dt))
    var = (sigma**2 / (2 * kappa)) * (1 - np.exp(-2 * kappa * dt))
    var = np.maximum(var, 1e-30)
    return -0.5 * (np.log(2 * np.pi * var) + (r_curr - mean)**2 / var)


def particle_filter_ou(data, dt, n_particles=500, rng_pf=None):
    """Particle filter for OU process parameters (kappa, theta, sigma).

    Returns weighted-average estimates (kappa_hat, theta_hat, sigma_hat).
    """
    if rng_pf is None:
        rng_pf = np.random.default_rng(0)

    # Initialise particles from broad priors
    kappa = rng_pf.gamma(2, 2, size=n_particles)     # positive, mode=2
    theta = rng_pf.normal(0, 2, size=n_particles)     # centred at 0
    sigma = rng_pf.gamma(2, 0.5, size=n_particles)    # positive, mode=0.5
    particles = np.column_stack([kappa, theta, sigma])
    weights = np.ones(n_particles) / n_particles

    # Subsample data for speed (take every 5th obs for long series)
    step = max(1, len(data) // 500)
    data_sub = data[::step]
    dt_sub = dt * step

    for t in range(1, len(data_sub)):
        # Update weights
        ll = ou_log_likelihood(data_sub[t-1], data_sub[t],
                               particles[:, 0], particles[:, 1],
                               particles[:, 2], dt_sub)
        log_w = np.log(weights + 1e-300) + ll
        log_w -= np.max(log_w)  # numerical stability
        weights = np.exp(log_w)
        weights /= np.sum(weights)

        # Effective sample size
        n_eff = 1 / np.sum(weights**2)
        if n_eff < n_particles / 2:
            # Systematic resampling
            cumw = np.cumsum(weights)
            u0 = rng_pf.uniform(0, 1 / n_particles)
            indices = np.searchsorted(cumw, u0 + np.arange(n_particles) / n_particles)
            indices = np.clip(indices, 0, n_particles - 1)
            particles = particles[indices].copy()
            weights = np.ones(n_particles) / n_particles

            # MCMC diversification (simple random walk)
            cov = np.cov(particles, rowvar=False)
            h = (4 / (n_particles * 5)) ** (1/7)  # Scott's rule
            noise = rng_pf.multivariate_normal(np.zeros(3), h**2 * cov,
                                                size=n_particles)
            proposals = particles + noise
            # Filter valid proposals (kappa>0, sigma>0)
            valid = (proposals[:, 0] > 0) & (proposals[:, 2] > 0)
            ll_old = ou_log_likelihood(data_sub[t-1], data_sub[t],
                                       particles[:, 0], particles[:, 1],
                                       particles[:, 2], dt_sub)
            ll_new = ou_log_likelihood(data_sub[t-1], data_sub[t],
                                       proposals[:, 0], proposals[:, 1],
                                       proposals[:, 2], dt_sub)
            accept = valid & (np.log(rng_pf.uniform(size=n_particles)) < (ll_new - ll_old))
            particles[accept] = proposals[accept]

    # Weighted average estimate
    est = np.sum(particles * weights[:, None], axis=0)
    return est[0], est[1], est[2]  # kappa, theta, sigma

7 Observations

  1. The estimation penalty has a clean formula. For one-shot estimation with calibration window T_{\mathrm{est}}, the asymptotic Sharpe ratio satisfies \mathrm{SR}_\infty = \sqrt{\theta/2}\,(1 + 2/(\theta T_{\mathrm{est}}))^{-1/2}. The penalty is governed by \theta T_{\mathrm{est}} — the number of mean-reversion timescales observed. Slow mean reversion (small \theta) requires proportionally longer calibration.

  2. The one-shot correlation channel is transient. Because \hat\mu is fixed after calibration and the OU process is Markovian, \mathrm{Cov}(\hat\mu, X_t) decays exponentially into the trading window. For long trading horizons, the Part 3 expected-PnL degradation vanishes and only the Part 2 variance penalty remains.

  3. Rolling re-estimation is a trailing estimator. A trader who continuously re-estimates \hat\mu using a rolling window of length W is effectively using a simple moving average — a Part 3 trailing estimator with permanent positive correlation. The resulting penalty (1 + 2/(\theta W))^{-1/2} has the same functional form but a fundamentally different character: it persists at all horizons.

  4. \hat\theta bias creates overconfidence, not SR loss. The finite-sample upward bias in \hat\theta does not degrade realised SR (which is scale-invariant in position size), but systematically inflates the trader’s SR prediction. This leads to over-allocated capital and underestimated drawdown risk — a more insidious failure mode than direct performance loss.

  5. Particle filtering tightens parameter distributions. The PF produces estimates of (\hat\theta, \hat\mu) with lower variance and reduced bias compared to MLE, translating into higher and more consistent realised SR. The improvement is most pronounced for short calibration windows where MLE estimation error is largest.

8 Further Exploration

  • Optimal calibration–trading split. Given a fixed total observation period T, how should one split it between calibration (T_{\mathrm{est}}) and trading (T_{\mathrm{trade}} = T - T_{\mathrm{est}})? The one-shot penalty improves with longer T_{\mathrm{est}} but trades off against the trading horizon over which SR is accumulated.
  • Online Bayesian estimation. Instead of a hard calibration/trading split, a Bayesian trader could continuously update the posterior over (\theta, \mu, \sigma) as each new observation arrives. This interpolates between the one-shot and rolling estimators.
  • Model misspecification. All results assume the true DGP is a stationary OU process. What happens when \theta or \mu change over time? The rolling estimator might then outperform the one-shot estimator by adapting to regime shifts.
  • Joint estimation and trading. In practice, the trader’s position itself affects market prices. Accounting for market impact introduces feedback between estimation and execution.
